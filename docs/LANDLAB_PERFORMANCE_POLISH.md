# LandLab — финальная полировка иконок и производительности

Дата проверки: 9 сентября 2026 года  
Исходная версия: `b7fb87391994f0409fee28afc150677472a7d33a`  
Архитектура: статические HTML, CSS и JavaScript; GitHub Pages  
Публикация в рамках задачи: не выполнялась

## 1. Замена стрелок и система иконок

- Все пользовательские Unicode-стрелки удалены из HTML, CSS и JavaScript.
- Добавлен один SVG-symbol `ll-icon-arrow`, от которого создаются направления вправо, вверх, вниз и по диагонали через CSS-трансформацию.
- Иконки используют `currentColor`, единый `stroke-width`, одинаковые окончания линий и фиксированный `viewBox`.
- Декоративные SVG помечены `aria-hidden="true"` и `focusable="false"`.
- Иконки заменены в навигации, hero, CTA услуг, ссылках кейсов, переходе к процессу, блоке об авторе, контактах, кнопке формы и footer.
- Повторная разметка кнопки после ошибки формы также возвращает SVG, а не системный символ.
- Проверка DOM: 14 SVG-экземпляров, пользовательских Unicode-стрелок — 0.

## 2. Найденные причины стоимости motion

- Три независимых обработчика scroll запускали три отдельных `requestAnimationFrame`-цикла.
- Скрипт портфолио обновлял состояния всех кейсов на каждом scroll-кадре, включая далёкие от viewport.
- Скрипт нижней части страницы вызывал `getBoundingClientRect()` для секций и элементов процесса во время прокрутки.
- `will-change` постоянно удерживал большое количество слоёв, включая изображения и полноэкранные поверхности.
- Позиция большого radial-gradient в контактах пересчитывалась во время scroll, вызывая перерисовку поверхности.
- На мобильных одновременно использовались clip-path, image filter, большой transform и backdrop blur.
- Первый portfolio JPEG загружался eager, хотя расположен ниже первого экрана.

## 3. Оптимизация JavaScript

- Добавлен общий `motion-core.js`: один пассивный scroll-listener и один rAF-батч для всех сцен.
- Hero, услуги, портфолио, процесс, About и контакт подписаны на общий кадр.
- Геометрия секций кэшируется; повторное измерение происходит при загрузке, resize, orientation change и фактическом изменении размеров.
- Чтение геометрии и запись CSS-переменных разделены: на обычном scroll layout повторно не измеряется.
- Далёкие от viewport секции пропускают вычисления и style updates.
- `IntersectionObserver` включает compositing-подсказки только для близких к viewport сцен.
- Mobile case parallax отключён; reveal остаётся через более короткий transform/opacity-переход.
- Magnetic CTA обрабатывает pointermove не чаще одного rAF-кадра.
- Активное состояние процесса не переписывается, если индекс шага не изменился.

## 4. Оптимизация CSS

- Постоянные `will-change` сброшены и включаются только на активных сценах.
- Анимируемый radial-gradient контактов заменён на статичный фон; движение оставлено на лёгком outline-слое через transform.
- Для визуала кейса добавлен `contain: paint`.
- На мобильных service и case reveal переведены с clip-path на transform/opacity.
- На мобильных изображениях кейсов отключён постоянный filter и уменьшен диапазон scale.
- Мобильный work-intro использует transform/opacity вместо анимируемой полноэкранной маски.
- На ширине до 980 px отключён дорогой backdrop blur фиксированной навигации; сохранена плотная полупрозрачная поверхность.

## 5. Mobile и iOS

- Системные/emoji-стрелки полностью исключены; результат не зависит от Apple Color Emoji или системного шрифта.
- Для iPhone-класса уменьшены travel и scale hero-декора, сокращена высота перехода к портфолио.
- На мобильных не выполняется case parallax и не анимируются крупные clip-path-маски.
- Tablet и mobile по-прежнему используют разложенные секции услуг и кейсов без desktop scroll trap.
- Используемые ранее `svh` сохранены; новые зависимости и Safari-хаки не добавлялись.

## 6. Изображения

- Все четыре изображения портфолио сохраняют исходные размеры `1280 × 605/607` в разметке.
- Для всех указаны `loading="lazy"`, `decoding="async"` и `fetchpriority="low"`.
- Изображения успешно загружаются при приближении к соответствующему кейсу.
- Качество и сами JPEG-файлы не изменялись.

## 7. Sticky-сцены

- Desktop-концепции hero, услуг, перехода к портфолио, кейсов и процесса сохранены.
- Progress, активные услуги, заголовки, изображения и переходы продолжают обновляться через CSS-переменные.
- На tablet/mobile уже существующее освобождение длинных sticky-сцен сохранено и дополнительно облегчено.
- Reduced-motion переводит закреплённые сцены в обычный поток и показывает контент без choreography.

## 9. Оставшиеся ограничения

- Физический iPhone и Safari Web Inspector в этой задаче не использовались; iOS-профиль проверен через mobile viewport и CSS media rules в Chromium.
- Встроенная браузерная сессия не предоставила timeline/trace long-task profiler, поэтому конкретное значение FPS не заявляется.
- На desktop сохранены несколько кратких clip-path-переходов — это часть принятой режиссуры. Они выполняются только рядом с активной сценой.
- Реальная частота кадров зависит от устройства, браузера, фоновой нагрузки и скорости загрузки внешних Google Fonts.
